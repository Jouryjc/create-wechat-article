# 已踩过的坑

下面这些问题都是真实踩过的，不是抽象建议。

## 1. 在线 Doocs 不稳定

表现：

- 页面打不开
- `复制` 按钮不可用
- 拦截不到剪贴板
- 页面 DOM 改了导致自动化失效

结论：

- 默认不要依赖在线 Doocs
- 本地渲染才是主路径

## 2. 本地渲染有样式，但发到公众号后变弱

表现：

- HTML 本地看起来像 Doocs
- 草稿里却像“没美化”

根因：

- 发布时只截了正文片段
- 外层 body 样式丢了
- 微信又继续过滤 CSS

修法：

- 保留 body 级样式
- 提前做微信兼容内联化

## 3. 封面比例不适合公众号

表现：

- 16:9 看起来像视频封面
- 缩略图裁成方形后标题残缺

结论：

- 默认用 `2.35:1`
- 强制保留居中 `1:1` 安全区

## 4. 列表丢数字 / 丢黑点

表现：

- 有序列表没有数字
- 无序列表没有黑点

根因：

- `ul` 被设成了 `list-style: none`
- 发布时没有补 marker 相关内联样式

修法：

- `ul`: `list-style-type: disc`
- `ol`: `list-style-type: decimal`
- `li`: `display: list-item`

## 5. 双黑点

表现：

- 同一个列表项前面出现两个黑点

根因：

- 原生 marker 恢复了
- `li` 文本前面本身还残留了字面量 `•`

修法：

- 发布前清洗 `<li>` 开头的字面量 marker

## 6. 代码块在公众号里失真

表现：

- 代码背景没了
- 行距变挤
- 字体层次弱

结论：

- 代码块样式不能只靠全局 CSS
- 要提前把关键视觉属性内联化

## 7. 不要只改单篇文章

如果某个问题在一篇文章里出现，大概率以后还会继续出现。

更优先的修法应该是：

- 先改主题层
- 再改发布兼容层
- 最后才考虑改单篇 markdown
